## Product goal (restated)

```
screen ──► extract state ──► GameState ──► DecisionEngine ──► top-3 moves
            (items, gold, XP,                ▲
             level, HP, round,               │
             shop, units, opponents)   meta knowledge (comps, level plan,
                                        items, units) refreshed offline
```

The project succeeds when a player gets a correct top-3 move, built from
the live screen, inside the decision window.

## Verdict

**The engine is ahead of the eyes.** The decision core, knowledge cache and
ingestion work well and have tests. Perception covers only one of the nine
state fields (shop). Nothing connects screen → GameState → recommendation
yet, so the product cannot run on a real game. Work has stalled since
2026-09-16 (15 days with no commits). The docs still say CV is "deferred"
even though the last six commits were CV work.

Estimated completion against the product goal: **~35%**. Engine ~65%,
knowledge ~55%, perception ~10%, integration 0%.

## Risks

1. **Board-unit recognition (3D models)** is the hardest perception task
   and has no design yet. Mitigations: item and trait-panel inference, bench
   first, and user confirmation as a fallback.
2. **Set / patch churn.** Templates are tied to set 18 and the Korean
   client. A set change invalidates every card template. Recalibration has
   to be a one-command, under-1-hour job.
3. **Stale knowledge** silently produces confident but wrong advice. A
   staleness guard is required before any live use.
4. **Riot third-party policy.** Overlays that prescribe in-game decisions
   may be restricted. Verify the current TFT developer policy before building
   any overlay. Screen reading only: no memory reading and no input
   automation.
5. **Shallow stats.** Eight comps with nominal sample sizes limit "highest
   winrate" claims. Long-term fix: Riot `tft-match-v1` own-data pipeline.
6. **Doc drift.** README and ROADMAP contradict the actual direction of work.
